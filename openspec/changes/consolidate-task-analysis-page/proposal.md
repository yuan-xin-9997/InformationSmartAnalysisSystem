## Why

当前「分析任务」「定时任务」「推送管理」三个页面各自独立，但它们本质上是围绕同一实体——分析任务——的三段配置：分析什么（任务与信息源）、何时分析（定时调度）、分析完推给谁（推送）。三页分离导致关系不直观：用户要在「定时任务」页用下拉选「所属分析任务」、在「推送管理」页用多选勾「分析任务」，配置散落三处，任务与它的调度/推送之间缺乏一目了然的归属关系。把它们浓缩为一个以任务为中心的「任务分析」页，在任务编辑弹窗内一体化配置「分析 + 定时 + 推送」，能显著降低心智负担与跳转成本。

## What Changes

- **三页合一**：移除独立的「定时任务」「推送管理」两个页面与侧边栏入口，将其能力并入「分析任务」页并重命名为「任务分析」。原 `/analysis-tasks` 路由保留（或重命名为 `/task-analysis` 并对旧路径做重定向），原 `/scheduled-jobs`、`/push-management` 路由重定向到「任务分析」页。
- **任务列表增强**：每个任务卡片在现有信息（名称、模式、绑定源数、创建时间）基础上，新增「定时」与「推送」状态摘要（如 `定时：每天9点 / 未配置`、`推送：3 收件人·完成后自动 / 未配置`），让调度与推送归属一目了然。
- **编辑弹窗一体化**：任务编辑弹窗由单页表单改为分区/分 Tab 结构：
  - **基本信息**：名称、说明、分析模式（逐条/汇总/自定义）、条目选择策略、绑定信息源、自定义条目选择、高级配置（保留现有全部能力）。
  - **定时分析**：启用开关、执行模式（全量/增量）、触发类型（cron/间隔）、cron 表达式或间隔秒数、快捷预设。每任务至多一条定时配置。
  - **推送配置**：启用开关、事件类型、收件人、触发方式（完成后自动/定时/仅手动）、定时参数、每封邮件最大事件数。每任务至多一条推送配置。
- **BREAKING：推送规则由多任务改为单任务（1:1）**：现有 `PushRule.task_ids`（JSON 数组，可多选任务）重构为每任务一条推送配置（1:1）。多任务规则在迁移时按任务拆分为多条单任务配置（收件人/事件类型/触发方式等保持不变）。该变更使推送配置真正归属于任务，与「编辑里配置推送」的诉求一致；失去的仅是「一条规则管多任务」的管理便利，相同收件人仍可在多任务上分别配置实现等价效果。
- **定时任务改为 1:1**：`ScheduledJob` 与 `AnalysisTask` 由当前的 N:1（无唯一约束，一任务可多条定时）收敛为 1:1（每任务至多一条定时配置）。迁移时每任务保留最近一条定时，多余者归档删除。
- **SMTP 配置与推送历史迁移**：原「推送管理」页的全局 SMTP 配置迁移为「任务分析」页底部的全局「邮件通道（SMTP）」折叠区（仍为单例、页面优先于 app.json）；推送历史由「按规则查看」改为「按任务查看」，在任务编辑弹窗或任务卡片中入口可见。
- **权限收敛**：移除页面权限键 `scheduled_jobs`、`push_management`；保留 `analysis_tasks` 键并改显示名为「任务分析」。曾持有 `scheduled_jobs` 或 `push_management` 权限的用户在迁移时自动授予 `analysis_tasks`，避免功能丢失。

## Capabilities

### New Capabilities
- `task-analysis-workbench`: 以任务为中心的「任务分析」统一工作台——分析任务 CRUD、信息源绑定、分析模式与条目选择策略、每任务一体化的定时分析配置，以及推送配置与结果入口的集成界面。涵盖三页合一后的页面外壳、任务列表状态摘要、编辑弹窗分区结构、定时任务 1:1 化与迁移。

### Modified Capabilities
- `event-push`: 推送规则管理界面由独立的「推送管理」页迁入「任务分析」任务编辑弹窗；数据模型由多任务（`task_ids` 数组）改为单任务 1:1；移除独立推送管理页与 `push_management` 权限键；SMTP 配置与推送历史的展示位置随之迁移。推送的增量水位线、三种触发方式、邮件渲染发送、SMTP 分层与历史记录等核心语义不变。

## Impact

- **前端**：
  - 新增/重构 `src/app/frontend/src/views/AnalysisTasks.vue` 为「任务分析」统一页（任务列表状态摘要 + 分区编辑弹窗 + 全局 SMTP 折叠区 + 按任务推送历史）；移除 `ScheduledJobs.vue`、`PushManagement.vue`（或内联合并）。
  - `src/app/frontend/src/router/index.ts`：移除 `/scheduled-jobs`、`/push-management` 路由，增加旧路径重定向；`/analysis-tasks` 路由 meta 标题改为「任务分析」。
  - `src/app/frontend/src/layouts/MainLayout.vue`：侧边栏移除「定时任务」「推送管理」入口，「分析任务」改为「任务分析」。
  - `src/app/frontend/src/api/scheduledJobs.ts`、`push.ts`、`tasks.ts`：按 1:1 模型与统一保存接口调整类型与方法。
- **后端**：
  - `models/scheduled_job.py`：`ScheduledJob` 增加 `task_id` 唯一约束（1:1）。
  - `models/push.py`：`PushRule` 由 `task_ids: list` 改为 `task_id` 外键（1:1，唯一）；迁移已有数据。
  - `api/scheduled_jobs.py`、`api/push.py`：接口适配 1:1 语义（可能合并为任务维度的一体化保存/读取端点）；保留手动触发、立即执行、历史、SMTP 等端点。
  - `services/scheduler.py`、`services/push/*`：适配 1:1 模型；`on_run` 自动推送、定时调度、水位线等逻辑保持不变。
  - `core/pages.py`：移除 `scheduled_jobs`、`push_management` 页面键；`analysis_tasks` 改显示名「任务分析」；权限迁移逻辑。
- **数据库迁移**：SQLite 数据文件 `data/app.sqlite3` 需一次性迁移脚本——拆分多任务推送规则、收敛多余定时任务、迁移用户页面权限。
- **测试**：迁移脚本单测；1:1 推送/定时 CRUD 与唯一约束单测；任务编辑弹窗一体化保存冒烟；权限迁移后访问控制冒烟；现有推送/调度核心逻辑回归。
- **文档**：更新 `README.md`（页面介绍）、需求规格说明书、设计说明书；`Jenkinsfile` 无依赖/启动变化则不动。
