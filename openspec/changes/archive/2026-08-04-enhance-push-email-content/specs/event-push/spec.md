## MODIFIED Requirements

### Requirement: 邮件渠道渲染与发送

系统 SHALL 通过邮件渠道推送事件：把待推送事件集渲染为一封邮件（包含 HTML 正文与纯文本备用正文，正文 MUST 以北京时间显示事件时间），通过 SMTP 发送到规则配置的收件人。邮件正文 MUST 把分析结果的 Markdown 渲染为 HTML（MUST NOT 输出原生 Markdown 标记）。`per_item` 事件邮件正文 MUST 包含文件信息（文件名、文件路径）与文章信息（标题、作者、作者单位、发布时间、页数；字段为空则不显示该行）；`aggregate` 事件无文件/文章信息，仅含任务名/类型/来源/时间与渲染后的分析结果。邮件渠道 MUST 设计为可扩展（当前仅实现邮件，后续可新增其他渠道而不改动推送规则与触发逻辑）。SMTP 发送失败时 MUST 不更新水位线，以便下次推送重试。

#### Scenario: 渲染并发送邮件
- **WHEN** 一次推送有 3 条待推送事件且 SMTP 配置可用
- **THEN** 系统渲染包含这 3 条事件内容的邮件并发送到收件人，事件时间以北京时间显示

#### Scenario: 分析结果 Markdown 渲染为 HTML
- **WHEN** 待推送事件的分析结果内容含 Markdown 标记（标题 `#`、加粗 `**`、列表、表格等）
- **THEN** 邮件 HTML 正文把该 Markdown 渲染为对应的 HTML 元素（标题/加粗/列表/表格等），不出现原生 Markdown 标记

#### Scenario: per_item 事件含文件与文章信息
- **WHEN** 待推送事件为 `per_item` 且关联 `InfoItem` 具备文件名、作者、发布时间等元数据
- **THEN** 邮件正文展示该事件的文件名、文件路径、标题、作者、作者单位、发布时间、页数（为空的字段不显示该行）

#### Scenario: aggregate 事件不含文件信息
- **WHEN** 待推送事件为 `aggregate`
- **THEN** 邮件正文仅展示任务名/类型/来源/时间与渲染后的分析结果，不展示文件/文章信息

#### Scenario: 发送失败不推进水位线
- **WHEN** SMTP 发送失败
- **THEN** 系统不更新规则水位线，本次事件将在下次推送时重新尝试，并在推送历史中记录失败与错误信息
