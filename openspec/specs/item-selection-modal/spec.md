# item-selection-modal Specification

## Purpose

此能力描述分析任务页「自定义（指定条目）」模式下「选择条目」弹窗的条目选择体验：已选条目前排置顶集中展示（始终可见、可逐条取消、不受筛选/排序影响）、可浏览列表按列排序（标题/已分析/发布时间，跨分页服务端一致）与按列筛选（标题关键词 + 已分析状态），以及支撑这些能力的服务端条目查询接口扩展（按 ID 取已选、排除已选、白名单排序、标题模糊匹配）。

## Requirements
### Requirement: 已选条目前排置顶展示

「选择条目」弹窗 SHALL 在顶部设独立「已选条目」区，始终展示当前所有已选条目（标题、已分析、发布时间），每条提供取消选择控件。该区 MUST 不受当前排序/筛选条件影响而始终可见。下方「可浏览列表」MUST 排除已在已选区中的条目以避免重复。在可浏览列表中勾选条目 SHALL 将其移入已选区并从可浏览列表移除；在已选区取消选择 SHALL 将其移回可浏览列表（若符合当前筛选/排序/分页条件）。已选区条目数 SHALL 与 `custom_item_ids` 实时一致。

#### Scenario: 打开弹窗时预选条目展示在顶部
- **WHEN** 用户打开「选择条目」弹窗且任务已有若干预选条目
- **THEN** 顶部已选区列出这些预选条目的标题/已分析/发布时间，可浏览列表不包含这些条目

#### Scenario: 勾选可浏览列表条目移入已选区
- **WHEN** 用户在可浏览列表勾选一条条目
- **THEN** 该条移入顶部已选区、从可浏览列表消失，已选计数加 1

#### Scenario: 在已选区取消选择移回可浏览列表
- **WHEN** 用户在已选区对某条目取消选择
- **THEN** 该条从已选区消失，可浏览列表重新取数后该条重新出现（若符合当前条件），已选计数减 1

#### Scenario: 已选区不受筛选影响
- **WHEN** 用户设置筛选条件使某些已选条目不满足该筛选条件
- **THEN** 这些已选条目仍显示在顶部已选区，不被筛选隐藏

### Requirement: 条目列排序

可浏览列表 SHALL 支持点击「标题」「已分析」「发布时间」列表头按该列排序，再次点击同一列头 SHALL 切换升/降序，当前排序列与方向 SHALL 在表头以可视指示标记。排序 MUST 在服务端执行以保证跨分页一致。排序字段 MUST 限定在白名单（`title`/`published_at`/`analyzed`/`created_at`）内，未知字段 MUST 回退到默认排序（按 `id` 倒序）且不报错。未指定排序时 MUST 保持现状默认（按 `id` 倒序）。

#### Scenario: 点击列头升序排序
- **WHEN** 用户点击「标题」列头
- **THEN** 可浏览列表按标题升序排列，表头显示升序指示

#### Scenario: 再次点击切换为降序
- **WHEN** 用户在已升序状态下再次点击同一列头
- **THEN** 可浏览列表按该列降序排列，表头显示降序指示

#### Scenario: 排序跨分页一致
- **WHEN** 用户在排序状态下翻页
- **THEN** 每页均按该排序返回，跨页顺序连续一致

#### Scenario: 未指定排序时保持默认
- **WHEN** 弹窗打开且用户未点击任何列头
- **THEN** 可浏览列表按 `id` 倒序排列（与现状一致）

### Requirement: 条目列筛选

可浏览列表 SHALL 支持按「标题关键词」模糊筛选（大小写不敏感包含匹配），并 SHALL 保留现有「已分析」状态筛选；两者 MUST 可组合使用。筛选 MUST 在服务端执行并作用于可浏览列表；已选条目区 MUST 不受标题/已分析筛选影响。改变任一筛选条件 SHALL 将分页重置到第 1 页。

#### Scenario: 按标题关键词筛选
- **WHEN** 用户在标题关键词输入框输入关键词
- **THEN** 可浏览列表仅显示标题包含该关键词的条目（大小写不敏感）

#### Scenario: 关键词与已分析组合筛选
- **WHEN** 用户同时设置标题关键词与「已分析」筛选
- **THEN** 可浏览列表仅显示同时满足两者的条目

#### Scenario: 清空关键词恢复为已分析筛选结果
- **WHEN** 用户清空标题关键词输入
- **THEN** 可浏览列表恢复为仅按当前「已分析」筛选的结果

#### Scenario: 改变筛选重置到第 1 页
- **WHEN** 用户改变任一筛选条件（关键词或已分析）
- **THEN** 分页重置到第 1 页

### Requirement: 条目查询接口支持置顶/排序/筛选取数

`POST /api/info-sources/items/query` SHALL 接受可选参数：`ids`（仅返回指定 ID 的条目，用于取已选条目详情）、`exclude_ids`（排除指定 ID，用于可浏览列表去重已选）、`sort_by`（白名单字段 `title`/`published_at`/`analyzed`/`created_at`）、`order`（`asc`/`desc`）、`keyword`（标题模糊匹配）。接口 SHALL 在 SQL 层统一应用 `source_ids`、`analyzed`、`keyword`、`ids`、`exclude_ids` 过滤与排序后再分页，MUST NOT 在取行后再用 Python 二次过滤导致每页不足 `limit`。不传新参数时行为 MUST 与现状一致（按 `id` 倒序、无关键词/排除）。接口 MUST 对 `sort_by` 做白名单校验，MUST NOT 将用户输入直接拼入 SQL。

#### Scenario: 按 ids 取已选条目
- **WHEN** 请求携带 `ids=[1,2,3]`
- **THEN** 返回这 3 条条目，`total=3`

#### Scenario: exclude_ids 排除已选
- **WHEN** 请求携带 `exclude_ids=[5,6]`
- **THEN** 返回结果不含 id 为 5、6 的条目

#### Scenario: 服务端按白名单字段排序
- **WHEN** 请求携带 `sort_by=title` 且 `order=asc`
- **THEN** 返回条目按标题升序排列

#### Scenario: 标题关键词模糊匹配
- **WHEN** 请求携带 `keyword="报告"`
- **THEN** 返回条目的标题均包含「报告」（大小写不敏感）

#### Scenario: 向后兼容默认行为
- **WHEN** 请求仅携带 `source_ids`/`limit`/`offset`（不传任何新参数、不传 `analyzed`）
- **THEN** 返回按 `id` 倒序的分页结果，与现状一致

#### Scenario: analyzed 过滤在 SQL 层满额返回
- **WHEN** 请求携带 `analyzed=true`
- **THEN** 返回条目均为已分析，且每页返回 `limit` 条（修复现状取行后 Python 二次过滤导致每页不足 `limit` 的问题）

#### Scenario: 拒绝非白名单排序字段
- **WHEN** 请求携带 `sort_by` 为非白名单值（如 `password`）
- **THEN** 系统回退默认 `id` 倒序排序，不报错且不泄露错误
