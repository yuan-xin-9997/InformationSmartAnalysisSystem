# event-push Specification

## Purpose

把增量分析结果（事件）按管理员配置的推送规则，通过邮件渠道推送到指定邮箱。涵盖推送规则管理、事件选定、增量水位线、三种触发方式（分析任务完成后自动、按计划定时、手动触发）、邮件发送与 SMTP 配置分层（页面优先于 app.json）、推送历史记录。推送渠道设计为可扩展，当前仅实现邮件渠道。
## Requirements
### Requirement: 推送规则管理

系统 SHALL 允许管理员创建、查看、编辑、启用/停用、删除推送配置。每条推送配置 MUST 归属且仅归属一个分析任务（1:1），并 MUST 至少包含：所属分析任务、选定的事件类型（`per_item`、`aggregate` 或两者）、一个或多个收件人邮箱、触发方式（`on_run` / `scheduled` / `manual`）、启用状态；当触发方式为 `scheduled` 时 MUST 还包含调度参数（cron 表达式或间隔秒数）。推送配置 MUST 在「任务分析」页的任务编辑弹窗「推送配置」区管理，且仅对拥有 `analysis_tasks` 页面权限的用户可见。每个任务至多一条推送配置；为已存在推送配置的任务再次保存时 SHALL 更新该配置而非新建。

#### Scenario: 创建推送规则
- **WHEN** 管理员在任务 A 的编辑弹窗「推送配置」区勾选事件类型 `per_item`、收件人填 `a@example.com`、触发方式选 `on_run` 并保存
- **THEN** 系统为任务 A 创建一条归属任务 A 的推送配置，状态为启用，任务列表摘要更新

#### Scenario: 触发方式为 scheduled 时必须填写调度参数
- **WHEN** 管理员在「推送配置」区选择触发方式 `scheduled` 但未填写 cron 表达式或间隔秒数
- **THEN** 系统拒绝保存并返回明确的校验错误

#### Scenario: 普通用户无权访问推送管理
- **WHEN** 未被授予 `analysis_tasks` 页面权限的用户尝试访问「任务分析」页或调用推送配置接口
- **THEN** 系统拒绝访问（前端跳转、后端返回 403）

#### Scenario: 每任务至多一条推送配置
- **WHEN** 任务 A 已有一条推送配置，管理员再次在弹窗「推送配置」区修改收件人并保存
- **THEN** 系统更新任务 A 已有的那条推送配置，不新增第二条

### Requirement: 事件选定与增量水位线

系统 SHALL 把分析结果 `AnalysisResult` 作为推送的「事件」。每次为某条推送配置执行推送时，系统 MUST 选出满足该配置筛选条件（`task_id` 等于该配置所属任务、`result_type` 属于该配置选定事件类型）且 `id` 大于该配置当前水位线的分析结果，作为本次待推送事件集。每条推送配置 MUST 维护一个水位线（上次推送的最大 `AnalysisResult.id`）；推送成功后水位线 MUST 更新为本次推送事件集中的最大 `id`。水位线为空时（首次推送），系统 MUST 推送当前所有满足筛选条件的事件。

#### Scenario: 增量推送只发送新事件
- **WHEN** 配置水位线为 100，本次满足筛选条件的事件为 id 101、102、103
- **THEN** 系统只推送 id 101、102、103 的事件，并在推送成功后将水位线更新为 103

#### Scenario: 首次推送发送全部匹配事件
- **WHEN** 配置水位线为空，当前满足筛选条件的事件有 5 条
- **THEN** 系统推送这 5 条事件，推送成功后水位线更新为其中最大 id

#### Scenario: 仅按规则选定的任务与事件类型筛选
- **WHEN** 任务 A 的推送配置只选定了事件类型 `per_item`
- **THEN** 系统只选取任务 A 的 `per_item` 类型分析结果，任务 A 的 `aggregate` 结果与其他任务的结果均不被选中

### Requirement: 分析任务完成后自动推送

当一条启用状态的推送规则触发方式为 `on_run` 时，系统 MUST 在其选定的任一分析任务成功完成一次运行（`run_analysis` 状态置为 `succeeded`）后，自动为该规则执行一次增量推送。分析任务失败时 MUST NOT 触发推送。

#### Scenario: 任务成功完成后触发自动推送
- **WHEN** 规则触发方式为 `on_run` 且选定任务 A，任务 A 的一次运行成功完成并新生成了分析结果
- **THEN** 系统自动为该规则执行一次增量推送，把新生成的事件发送到规则配置的收件人

#### Scenario: 任务失败时不触发推送
- **WHEN** 规则选定任务 A 的一次运行以失败结束
- **THEN** 系统不触发该规则的推送

### Requirement: 按计划定时推送

当一条启用状态的推送规则触发方式为 `scheduled` 时，系统 MUST 按其调度参数（cron 表达式或间隔秒数）注册到进程级调度器，周期性地为该规则执行增量推送。规则的启用/停用与调度参数变更 MUST 实时同步到调度器，无需重启进程。

#### Scenario: 按间隔周期性推送
- **WHEN** 规则触发方式为 `scheduled`、间隔 3600 秒且处于启用状态
- **THEN** 系统每个间隔周期为该规则执行一次增量推送，把水位线之后的新事件发送出去

#### Scenario: 停用规则后不再定时推送
- **WHEN** 管理员把一条 `scheduled` 规则停用
- **THEN** 调度器立即移除该规则的定时触发，不再产生新的定时推送，直到规则被重新启用

### Requirement: 手动触发推送

系统 SHALL 允许管理员在「任务分析」页对某任务的推送配置手动触发一次推送。手动推送 MUST 同样遵循增量水位线语义（只推送水位线之后的新事件），并在推送完成后在页面可见推送结果。

#### Scenario: 手动触发推送当前新事件
- **WHEN** 管理员在任务 A 的卡片上点击「立即推送」，此时该任务推送配置水位线之后存在 3 条新事件
- **THEN** 系统立即执行一次推送把这 3 条事件发送到收件人，并在推送历史中记录本次结果

#### Scenario: 无新事件时手动推送提示无内容
- **WHEN** 管理员手动触发推送但该任务推送配置水位线之后不存在新事件
- **THEN** 系统不发送邮件，并在推送历史中记录本次状态为「无新事件」

### Requirement: 邮件渠道渲染与发送

系统 SHALL 通过邮件渠道推送事件：把待推送事件集渲染为一封邮件（包含 HTML 正文与纯文本备用正文，正文 MUST 以北京时间显示事件时间），通过 SMTP 发送到规则配置的收件人。邮件正文 MUST 把分析结果的 Markdown 渲染为 HTML（MUST NOT 输出原生 Markdown 标记）。`per_item` 事件邮件正文 MUST 包含文件信息（文件名、文件路径）与文章信息（标题、作者、作者单位、发布时间、页数；字段为空则不显示该行）；`aggregate` 事件无文件/文章信息，仅含任务名/类型/来源/时间与渲染后的分析结果。邮件渠道 MUST 设计为可扩展（当前仅实现邮件，后续可新增其他渠道而不改动推送规则与触发逻辑）。SMTP 发送失败时 MUST 不更新水位线，以便下次推送重试。

#### Scenario: 渲染并发送邮件
- **WHEN** 一次推送有 3 条待推送事件且 SMTP 配置可用
- **THEN** 系统渲染包含这 3 条事件内容的邮件并发送到收件人，事件时间以北京时间显示

#### Scenario: 分析结果 Markdown 渲染为 HTML
- **WHEN** 待推送事件的分析结果内容含 Markdown 标记（标题 `#`、加粗 `**`、列表、表格等）
- **THEN** 邮件 HTML 正文把该 Markdown 渲染为对应的 HTML 元素（标题/加粗/列表/表格等），不出现原生 Markdown 标记

#### Scenario: per_item 事件含文件与文章信息
- **WHEN** 待推送事件为 `per_item` 且关联 `InfoItem` 具备文件名、作者、发布时间等元数据
- **THEN** 邮件正文展示该事件的文件名、文件路径、标题、作者、作者单位、发布时间、页数（为空的字段不显示该行）

#### Scenario: aggregate 事件不含文件信息
- **WHEN** 待推送事件为 `aggregate`
- **THEN** 邮件正文仅展示任务名/类型/来源/时间与渲染后的分析结果，不展示文件/文章信息

#### Scenario: 发送失败不推进水位线
- **WHEN** SMTP 发送失败
- **THEN** 系统不更新规则水位线，本次事件将在下次推送时重新尝试，并在推送历史中记录失败与错误信息

### Requirement: SMTP 配置分层与页面优先

系统 SHALL 支持两处 SMTP 配置来源：「任务分析」页的全局 SMTP 配置区（持久化到数据库）与 `config/app.json` 的 `email` 段。页面配置 MUST 优先于 `app.json`；当页面未配置时回退使用 `app.json` 的 `email` 段。当两处均未提供发送邮件所需的最小配置（SMTP 主机、发件人；密码按服务器要求）时，系统 MUST 返回明确错误而不静默失败。SMTP 配置中的敏感字段（密码等）在通过接口返回时 MUST 脱敏显示。

#### Scenario: 页面配置优先于 app.json
- **WHEN** 「任务分析」页已保存 SMTP 配置，且 `app.json` 的 `email` 段也配置了 SMTP
- **THEN** 系统发送邮件时使用页面保存的 SMTP 配置

#### Scenario: 页面未配置时回退 app.json
- **WHEN** 「任务分析」页未保存 SMTP 配置，但 `app.json` 的 `email` 段配置了 SMTP
- **THEN** 系统发送邮件时回退使用 `app.json` 的 `email` 段配置

#### Scenario: 两处都缺失时明确报错
- **WHEN** 页面与 `app.json` 均未配置 SMTP 主机等最小必需项
- **THEN** 系统在尝试推送时返回明确错误信息，不发送邮件，且不更新水位线

#### Scenario: 接口返回时密码脱敏
- **WHEN** 管理员通过接口读取 SMTP 配置
- **THEN** 密码等敏感字段以脱敏形式返回，不泄露明文

### Requirement: SMTP 配置管理与连通性测试

系统 SHALL 允许管理员在「任务分析」页的全局 SMTP 配置区读取与保存 SMTP 配置，并提供「发送测试邮件」功能以验证配置是否可用。测试邮件 MUST 发送到管理员指定的测试收件人，测试结果（成功/失败及错误信息）MUST 即时返回给页面。

#### Scenario: 保存 SMTP 配置
- **WHEN** 管理员在「任务分析」页 SMTP 配置区填写 SMTP 主机、端口、发件人、用户名、密码并保存
- **THEN** 系统持久化该配置，后续发送邮件使用该配置

#### Scenario: 发送测试邮件验证配置
- **WHEN** 管理员填写测试收件人并点击「发送测试邮件」
- **THEN** 系统用当前生效的 SMTP 配置向测试收件人发送一封测试邮件，并把成功或失败结果返回页面

### Requirement: 推送历史记录

系统 MUST 为每次推送执行（无论成功、失败或无新事件）记录一条推送历史，包含：所属推送配置（及其归属任务）、触发方式、收件人、推送事件数量、状态（成功/失败/无新事件）、错误信息、执行时间（北京时间显示）。系统 SHALL 在「任务分析」页按任务提供推送历史的查看。

#### Scenario: 成功推送后记录历史
- **WHEN** 一次推送成功发送了 3 条事件
- **THEN** 系统记录一条状态为成功、事件数量为 3 的推送历史，执行时间以北京时间显示

#### Scenario: 失败推送记录错误信息
- **WHEN** 一次推送因 SMTP 错误失败
- **THEN** 系统记录一条状态为失败的推送历史，并保存错误信息以便排查

### Requirement: 邮件附件

系统 SHALL 在推送 `per_item` 事件时，把文章原文件与内嵌图表图片作为邮件附件一并发送。原文件附件仅对 `local_folder` 源生效（从 `InfoItem.external_id` 读取）；`website`/`freshrss` 源无原文件附件。图表附件从 `InfoItemFigure.storage_path` 读取。附件读取 MUST 复用文件服务的路径校验（原文件 `is_relative_to` 源 `folder_path`、图表 `is_relative_to` `figures_dir`）防路径穿越。`aggregate` 事件无附件。单文件超过大小上限（默认 10MB）时 MUST 跳过该附件并记日志，不中断推送；文件不存在或路径越界时 MUST 跳过该附件。

#### Scenario: per_item 事件附带原文件与图表附件
- **WHEN** 推送一个 `per_item` 事件，其关联 `InfoItem` 属于 `local_folder` 源且有原文件与 2 张图表
- **THEN** 邮件附带原文件附件与 2 张图表图片附件

#### Scenario: 非 local_folder 源不附原文件
- **WHEN** 推送一个 `per_item` 事件，其信息源为 `website` 或 `freshrss`
- **THEN** 邮件不附带原文件附件（图表若存在仍附带）

#### Scenario: 路径越界的文件不被附加
- **WHEN** 附件文件路径经解析后不在源 `folder_path` 或 `figures_dir` 范围内
- **THEN** 系统跳过该附件（不读取、不附加），不报错

#### Scenario: 超大小上限的附件被跳过
- **WHEN** 某附件文件大小超过上限（如 10MB）
- **THEN** 系统跳过该附件并记日志，其余附件正常发送，推送不中断

#### Scenario: aggregate 事件无附件
- **WHEN** 推送一个 `aggregate` 事件
- **THEN** 邮件不附带任何附件

### Requirement: 邮件正文内嵌图表

系统 SHALL 在推送 `per_item` 事件时，把该事件关联的图表图片以 `Content-ID`（CID）方式内嵌进邮件 HTML 正文：正文相应位置渲染为 `<img src="cid:<cid>">`，图表字节作为 `multipart/mixed` 的内联图片 MIME 部分（`Content-Disposition: inline`，带 `Content-ID` 头）随邮件一并发出，使邮件客户端无需回访任何外部接口即可直接显示图表。图表字节 MUST 复用「邮件附件」同一来源（`InfoItemFigure.storage_path`，经 `figures_dir` 路径校验），不引入新的读取路径。每个图表 MUST 拥有唯一的 CID。内嵌图表 MUST 与图表附件共存（图表既在正文显示、又作为附件可下载）。`aggregate` 事件无图表，正文 MUST NOT 出现图表。`per_item` 事件无图表时，正文 MUST NOT 出现空占位或破损图片标记。图表读取失败（文件不存在、路径越界、超大小上限）时 MUST 跳过该图表的内嵌（与附件跳过语义一致），不中断推送。

#### Scenario: per_item 事件正文内嵌图表

- **WHEN** 推送一个 `per_item` 事件，其关联 `InfoItem` 有 2 张图表且文件可读
- **THEN** 邮件 HTML 正文在分析结果后渲染 2 个 `<img src="cid:...">`，邮件附带 2 个内联图片 MIME 部分（各带唯一 `Content-ID`），邮件客户端打开即可直接看到这 2 张图表

#### Scenario: 图表同时作为附件

- **WHEN** 一个 `per_item` 事件的图表被内嵌进正文
- **THEN** 该图表同时作为邮件附件（`Content-Disposition: attachment`）发送，收件人可下载

#### Scenario: 无图表的 per_item 事件不出现占位

- **WHEN** 推送一个 `per_item` 事件但其 `InfoItem` 无图表
- **THEN** 邮件正文不出现 `<img>` 标记或破损图片占位，邮件正常发送

#### Scenario: aggregate 事件不内嵌图表

- **WHEN** 推送一个 `aggregate` 事件
- **THEN** 邮件正文不含任何内嵌图表

#### Scenario: 图表读取失败时跳过内嵌

- **WHEN** 一个图表文件不存在或路径越界
- **THEN** 系统跳过该图表的内嵌（也不作为附件），记日志，其余图表正常内嵌，推送不中断

### Requirement: 邮件内容留存与预览

系统 MUST 在每次推送执行发送邮件后，把该次实际渲染并发送的邮件内容留存到推送历史：包括邮件主题、HTML 正文（内嵌图表随正文一并留存，可在预览中直接显示）、附件清单（原文件名与图表文件名，以及被跳过附件的摘要）。当一次推送因事件数超过每邮件上限而分多批发送多封邮件时，系统 MUST 留存各批邮件内容（可合并展示）。系统 SHALL 在「任务分析」页推送历史中，对至少成功发出 1 封邮件的记录提供「预览」入口，点击后以与邮件一致的形式渲染该邮件 HTML（含内嵌图表）。预览 MUST 仅对拥有 `analysis_tasks` 页面权限的用户可用。未发出邮件的记录（`no_new`、或发送前失败的 `failed`）MUST NOT 提供预览。

#### Scenario: 成功推送留存邮件内容

- **WHEN** 一次推送成功发送了含 2 个 `per_item` 事件（各 1 张图表）的邮件
- **THEN** 该推送历史记录留存邮件主题、HTML 正文（含 2 张内嵌图表，可在预览中直接显示）与附件清单（2 个图表文件名），执行时间以北京时间显示

#### Scenario: 推送历史预览邮件内容

- **WHEN** 管理员在推送历史中对一条已成功发送的记录点击「预览」
- **THEN** 系统弹出预览层，以与邮件一致的形式渲染该邮件 HTML，内嵌图表直接可见

#### Scenario: 多批邮件合并预览

- **WHEN** 一次推送分 2 批发送了 2 封邮件，管理员点击该记录「预览」
- **THEN** 预览层依次展示 2 封邮件的内容（各含其主题、正文、图表）

#### Scenario: 未发送邮件的记录不可预览

- **WHEN** 管理员对一条状态为 `no_new`（无新事件）的推送记录操作
- **THEN** 该记录不提供「预览」入口

#### Scenario: 预览受页面权限保护

- **WHEN** 未被授予 `analysis_tasks` 页面权限的用户调用预览接口
- **THEN** 系统拒绝访问（前端不展示入口、后端返回 403）
