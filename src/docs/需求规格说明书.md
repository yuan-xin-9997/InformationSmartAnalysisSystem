# 需求规格说明书 — 信息智能分析系统

## 1. 系统概述

信息智能分析系统（InformationSmartAnalysisSystem）面向给定信息源进行智能分析。用户可添加多种信息源、创建分析任务并绑定信息源、查看信息源状态、触发分析（含基于新增内容的增量分析），分析过程调用大模型接口。

## 2. 用户角色

| 角色 | 说明 |
|---|---|
| 管理员（admin） | 拥有全部页面权限；可管理用户页面权限；可操作所有功能 |
| 普通用户（user） | 可见页面由管理员在权限管理页配置 |

用户与角色维护在 `data/password.txt`（格式 `username:password:role`），修改后新用户在下次登录时自动同步到数据库。

## 3. 功能需求

### 3.1 登录与权限（基础模块）

- FR-AUTH-1：系统支持用户名/密码登录，凭证来源于 `data/password.txt`。
- FR-AUTH-2：登录成功颁发 JWT；未认证请求被拒绝（401）。
- FR-AUTH-3：管理员默认拥有全部页面权限；普通用户的可见页面由管理员配置。
- FR-AUTH-4：前端按权限渲染侧边栏，后端按页面权限拦截未授权 API（403）。
- FR-AUTH-5：页面权限键固定为：`dashboard` / `info_sources` / `analysis_tasks` / `scheduled_jobs` / `task_center` / `system_config` / `permission`（`permission` 仅管理员，不可授予普通用户；其余键均可由管理员授予普通用户）。

### 3.2 信息源管理（核心）

- FR-SRC-1：支持添加信息源，类型包括：官方网站、指定本地文件夹、FreshRSS 指定源。
- FR-SRC-2：信息源支持编辑、删除。
- FR-SRC-3：可对信息源进行健康检查与手动同步；同步抓取新内容并去重存储。同步采用「增量 + 回补」：跳过已索引且未变更的条目，只读取新增/变更/尚未入库的条目，故大目录首次同步入库全部、后续同步仅处理增量。`max_items` 控制单次同步上限（本地文件夹默认 100000），超出部分下次同步继续回补。
- FR-SRC-4：展示信息源状态（ok/warning/error）、最近同步时间、条目数、最近错误。
- FR-SRC-5：可查看某信息源下的信息条目列表与详情。
- FR-SRC-6：`local_folder` 信息源同步时抽取文档元数据（标题/作者/作者单位/发布时间/页数）。元数据来源：PDF 取 `doc.metadata` 与 `page_count`，Word 取 `core_properties`，HTML 取 `<title>`/`<meta>`；**作者单位优先从首页正文启发式抽取**（匹配大学/学院/研究所/公司/实验室/Department/University 等机构关键词），抽取不到留空。
- FR-SRC-7：`local_folder` 信息源同步时提取文档内嵌位图（PDF 用 PyMuPDF `get_images`/`extract_image`，Word 用内嵌图片部件），按 `data/figures/YYYY/MM/DD/{item_id}_{index}.{ext}` 落盘并写 `InfoItemFigure` 记录；超 `max_figures_per_item` 截断并记日志。
- FR-SRC-8：同步时对缺元数据/图表的存量 `InfoItem` 补抽；支持 `POST /api/info-sources/{source_id}/items/{item_id}/reextract` 手动单文件重新抽取（幂等，清旧图重建，需 `info_sources` 页权限）。

### 3.3 分析任务（核心）

- FR-TASK-1：可创建分析任务，并绑定一个或多个信息源作为信息来源范围。
- FR-TASK-2：每个任务可展示所绑定信息源的状态情况。
- FR-TASK-3：可触发分析，支持「全量分析」与「增量分析」两种模式。
- FR-TASK-4：增量分析基于信息源新增内容，仅分析水位线之后的新条目。
- FR-TASK-5：分析调用大模型接口（OpenAI 兼容）；支持逐条分析（per_item）与汇总分析（aggregate）。
- FR-TASK-6：分析结果持久化，可按任务/运行查看；通过分析任务列表的「结果」按钮下钻进入任务结果详情页（路径 `/analysis-tasks/:id/results`，按运行批次分组、折叠展开 Markdown 渲染）查看，复用 `analysis_tasks` 权限，不再单设独立菜单页。
- FR-TASK-7：分析结果页（`TaskResults.vue`，由「分析任务」页「结果」按钮打开）采用三段式呈现：
  - `per_item` 结果依次展示：① 文件信息（文件名可点击在网页预览 + 文件路径）；② 文章基本信息（标题/作者/作者单位/发布时间/页数）+ 正文内嵌图表（缩略图可查看大图）；③ 文字分析结果（markdown 渲染）。
  - `aggregate` 汇总结果仅展示文字分析结果。
  - 所有时间字段以北京时间展示。
- FR-TASK-8：分析结果接口 `GET /api/analysis-tasks/{task_id}/results?run_id=` 扩展返回：`per_item` 结果携带 `source_file`（filename/file_path/title/author/author_affiliation/published_at/page_count/file_url/figures），`aggregate` 结果 `source_file` 为 null。
- FR-TASK-9：提供文件预览接口 `GET /api/info-sources/{source_id}/items/{item_id}/file`（PDF inline 预览、docx 下载、html/txt/md 以 `text/plain` 返回）与图表服务接口 `GET /api/info-sources/{source_id}/items/{item_id}/figures/{index}`（返回图表图片字节 + MIME）；均需 `analysis_tasks` 页权限。
- FR-TASK-10：自定义（指定条目）分析模式下，「选择条目」弹窗（`AnalysisTasks.vue`）增强：① 顶部「已选条目」区始终集中展示当前已选条目并可逐条取消，不受筛选/排序影响，可浏览列表排除已选以避免重复；② 可浏览列表「标题/已分析/发布时间」列表头可点击排序，支持升降序切换，排序跨分页服务端一致；③ 新增「标题关键词」模糊筛选，与现有「已分析」筛选可组合，共同作用于可浏览列表。后端 `POST /api/info-sources/items/query` 扩展可选参数 `ids`/`exclude_ids`/`sort_by`/`order`/`keyword`，排序字段经白名单（`title`/`published_at`/`analyzed`/`created_at`）校验防注入，未知字段回退默认 `id` 倒序，向后兼容（不传新参数行为不变）。

### 3.4 任务中心（基础模块）

- FR-TC-1：展示系统任务运行列表（信息源同步、分析任务执行）。
- FR-TC-2：展示每次运行的状态、摘要、错误、开始/结束时间。
- FR-TC-3：可查看每次运行的日志详情；可删除运行记录。

### 3.5 系统配置（基础模块）

- FR-CFG-1：只读展示 `config/app.json`（敏感字段脱敏）。
- FR-CFG-2：展示运行时信息（启动时间、PID、版本、监听地址、数据库/日志/数据目录）。

### 3.6 定时任务（核心）

- FR-SCH-1：可为分析任务配置定时任务，支持 cron 表达式与固定间隔（`interval_seconds`）两种触发方式。
- FR-SCH-2：一个分析任务可配置多个定时任务；每个定时任务可选择增量（`incremental`）或全量（`full`）模式。
- FR-SCH-3：定时任务支持启用/禁用、立即执行、编辑、删除；启用/禁用即时同步到进程内调度器。
- FR-SCH-4：定时触发的执行记录在任务中心查看（`TaskRun.scheduled_job_id` 关联来源定时任务）。

### 3.7 分析结果文件服务安全

- FR-SEC-1：文件预览接口与图表服务接口须防路径穿越：文件路径须 `is_relative_to` 源 `folder_path`、图表路径须 `is_relative_to` `figures_dir`，否则 403。
- FR-SEC-2：文件/图表接口须校验条目归属（`item.source_id == source_id`），否则 404；非 `local_folder` 源的文件预览返回 404。
- FR-SEC-3：HTML/HTM 文件不作 `text/html` 服务（统一以 `text/plain` 返回），防 XSS。
- FR-SEC-4：文件/图表接口需 `analysis_tasks` 页权限；重新抽取接口需 `info_sources` 页权限。

## 4. 非功能需求

- NFR-1：环境相关信息（IP、端口、用户名、密码、绝对路径）不得硬编码，须可配置（`config/app.json` + 环境变量覆盖）。
- NFR-2：展示时间须为北京时间（存储 UTC）。
- NFR-3：下载文件按 年/月/日 存放于 `data/downloads/`。
- NFR-4：`.gitignore` 包含 `logs/`，不包含 `data/` 目录。
- NFR-5：所有功能须有单元测试与冒烟测试且通过。
- NFR-6：支持 Windows（ps1）与 Linux（sh + systemd）两种部署运维方式。
- NFR-7：网页抓取优先使用集中的 WebFetch 服务。
- NFR-8：敏感配置（LLM Key、JWT 密钥、WebFetch Key 等）通过 `config/env.local` 管理，覆盖 `app.json`；该文件不被 Jenkins 部署覆盖、不入 Git，修改后重启生效。`app.json` 中敏感字段仅为占位符。LLM 客户端对未配置/占位符 Key/非 ASCII Key/请求超时给出清晰提示。

## 5. 信息源类型说明

| 类型 | 数据来源 | 增量方式 |
|---|---|---|
| 官方网站 | 通过 WebFetch 服务抓取站点 HTML，解析文章链接与正文 | 按 URL 去重，新 URL 视为新增 |
| 本地文件夹 | 扫描指定目录下文件（txt/md/pdf/docx/html），抽取文本 + 元数据（标题/作者/作者单位/发布时间/页数）+ 内嵌图表 | 按文件路径去重，内容变更则更新 |
| FreshRSS | 通过 Google Reader API 拉取指定信息流条目 | 按条目 ID 去重，可选抓取后标记已读 |
