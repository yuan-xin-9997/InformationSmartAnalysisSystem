# 设计说明书 - 信息智能分析系统

## 1. 总体架构

```
[浏览器(Vue3 SPA)] ──HTTP──► [FastAPI 后端]
                                ├─ 认证/权限 (JWT + password.txt)
                                ├─ 信息源适配器 (website / local_folder / freshrss)
                                │     └─► WebFetch 服务 (网页抓取)
                                ├─ 分析引擎 ─► LLM (OpenAI 兼容)
                                ├─ 后台 Worker (ThreadPoolExecutor)
                                ├─ 定时任务调度器 (APScheduler BackgroundScheduler, Asia/Shanghai)
                                │     └─ _fire -> 创建 TaskRun -> 提交 Worker (复用 run_analysis)
                                └─ SQLite (SQLAlchemy ORM)
```

前后端分离、单服务部署：FastAPI 同时提供 REST API 与前端静态资源托管（SPA 兜底）。

## 2. 技术选型

| 层 | 选型 |
|---|---|
| 后端 | Python 3.11 + FastAPI + Uvicorn |
| ORM | SQLAlchemy 2.x |
| 数据库 | SQLite |
| 鉴权 | python-jose(JWT) + bcrypt |
| HTTP | httpx |
| 文档解析 | PyMuPDF / python-docx / BeautifulSoup |
| 前端 | Vue 3 + Vite + TS + Element Plus + Pinia + Vue Router |

| 日志 | logging + TimedRotatingFileHandler（按天切割，北京时间） |
| 测试 | pytest |

## 4. 数据库设计（SQLite）

| 表 | 关键字段 | 说明 |
|---|---|---|
| `users` | id, username, password_hash, password_fingerprint, role | 从 password.txt 同步；fingerprint 用于跳过重复哈希 |
| `page_permissions` | user_id, page_key | 普通用户可见页面 |
| `info_sources` | id, name, type, config(JSON), status, last_sync_at, last_error, item_count | 信息源 |
| `info_items` | id, source_id, external_id, title, url, content, content_hash, published_at, analyzed, author, author_affiliation, article_published_at, page_count, extraction_method | 抓取条目；(source_id, external_id) 唯一；中 4 列为文章元数据（可空），由 `local_folder` 抽取；`extraction_method` 记录正文抽取来源（`text_layer`/`vision_llm`/`none`，可空） |
| `info_item_figures` | id, item_id(FK->info_items, CASCADE), figure_index, storage_path, mime, width, height, caption, created_at | 文档内嵌图表；`(item_id, figure_index)` 标识；由 `create_all` 自动建表 |
| `analysis_tasks` | id, name, description, config(JSON) | 分析任务 |
| `task_sources` | task_id, source_id, last_analyzed_item_id, last_analyzed_at | **增量水位线** |
| `task_runs` | id, kind(analysis/sync), ref_id, ref_name, mode, status, scheduled_job_id, started_at, finished_at, summary, error | 一次执行；`scheduled_job_id` 关联来源定时任务（可空，手动触发为空） |
| `analysis_results` | task_run_id, task_id, source_id, info_item_id, result_type, content | 分析产出 |
| `scheduled_jobs` | id, task_id(FK→analysis_tasks, CASCADE), name, mode(full/incremental), trigger_type(cron/interval), cron_expr, interval_seconds, enabled, last_run_at, last_run_status, next_run_at, created_at, updated_at | 定时任务定义；与 `analysis_tasks` 多对一 |
| `task_logs` | run_id, level, message, created_at | 运行日志 |

时间字段统一存 UTC，接口/前端展示转北京时间。

> 增量升级：`task_runs.scheduled_job_id` 列由 `init_db()` 启动时通过 `_ensure_column` 探测并自动添加，老库无需手动迁移；`scheduled_jobs` 表由 `Base.metadata.create_all` 自动创建。`info_items` 的 `author`/`author_affiliation`/`article_published_at`/`page_count` 列同样由 `init_db()` 通过 `_ensure_column` 自动补列；`info_item_figures` 表由 `Base.metadata.create_all` 自动创建。

## 5. 模块设计

### 5.1 认证与权限（core/security.py, core/deps.py）

- 启动与登录时解析 `password.txt`，bcrypt 哈希后 upsert 到 `users`（用 `password_fingerprint` 跳过未变更项）。
- 登录返回 JWT（含 username/role）；`get_current_user` 解析 JWT；`require_page(page_key)` 校验页面权限（admin 全放行）。
- 页面权限键：dashboard / info_sources / analysis_tasks / scheduled_jobs / task_center / system_config / permission（permission 仅 admin，不可授予普通用户；其余键可授予）。

### 5.2 信息源适配器（services/info_source/）

统一抽象接口：
```
InfoSourceAdapter.check_status() -> SourceStatus
InfoSourceAdapter.fetch_new_items(since=None, known_ids=None) -> list[InfoItemData]
```
`fetch_new_items` 采用「增量 + 回补」：返回 mtime 晚于 `since` 或不在 `known_ids` 中的条目，跳过已索引且未变更的条目（不重读内容），从而首次同步入库全部、后续同步只处理新增/变更。

- `website.py`：调用 WebFetch 服务 `POST /v1/fetch` 获取 HTML，BeautifulSoup 解析文章链接与正文；`known_ids`（已索引 URL）跳过，只抓新文章。
- `local_folder.py`：扫描目录，按扩展名抽取文本（pdf→PyMuPDF，docx→python-docx，其他→原生/BS4）。同步时同时抽取：
  - **正文（视觉兜底）**：PDF 优先读文本层 `page.get_text()`，用可读字符占比 + 最小长度评估质量；不达标且 `extraction.vision_fallback` 启用时，用 `page.get_pixmap(dpi=)` 渲染页面为 PNG，逐页调用 `LLMClient.chat_with_images`（多模态）提取文本，按页序拼接为 `content`。抽取来源记入 `extraction_method`（`text_layer`/`vision_llm`/`none`）。视觉 LLM 不可用/调用失败时优雅降级（记警告、保留原文本、不抛异常）；受 `max_ocr_pages` 截断。
  - **元数据**：标题/作者/发布时间/页数取自文档属性（PDF `doc.metadata`+`page_count`、Word `core_properties`、HTML `<title>`/`<meta>`）；**作者单位优先从首页正文启发式抽取**（匹配大学/学院/研究所/公司/实验室/Department/University 等机构关键词），抽取不到留空。
  - **图表**：提取 PDF（PyMuPDF `get_images`/`extract_image`）与 Word（内嵌图片部件）的内嵌位图，按 `data/figures/YYYY/MM/DD/{item_id}_{index}.{ext}` 落盘，写 `InfoItemFigure` 记录；超 `max_figures_per_item` 截断并记日志。无新依赖（不引入 Pillow）。
  - **存量回填**：同步时对缺元数据/图表、或 `extraction_method='none'`/`content` 为空的存量 `InfoItem` 补抽（仅选中本次同步前已存在条目，避免与新建条目图表冲突）；`reextract_item(source_id, item_id)` 服务支持单文件重新抽取（幂等，清旧图重建）。
- `freshrss.py`：Google Reader API（ClientLogin 认证 → stream/contents 拉取条目）。
- `factory.py`：按类型实例化适配器并校验必填配置。
- `sync.py`：同步任务，传入 `since=source.last_sync_at` 与 `known_ids`（批量加载已存在 external_id），按 (source_id, external_id) upsert，content_hash 检测内容变更；批量去重避免 N+1 查询。

### 5.3 分析引擎（services/analysis/）

- `llm_client.py`：OpenAI 兼容 `POST {base_url}/chat/completions`，Bearer 鉴权；初始化校验 api_key（占位符 / 非 ASCII / 未配置）给出清晰中文错误，请求超时单独提示「endpoint 不可达或响应过慢」。`chat(system,user)` 发纯文本；`chat_with_images(system,user,images)` 发多模态视觉消息（`image_url` + base64 data URI），供 PDF 视觉兜底抽取使用，复用同一模型/超时/重试。
- `prompts.py`：默认逐条/汇总提示词模板（可在任务 config 中覆盖）。
- `engine.py`：`run_analysis(run_id, task_id, mode)` 编排：
  1. 遍历任务绑定的源；
  2. 按 `config.selection_strategy` 选择候选条目：
     - `sequential`（默认）：增量取 `id > 水位线` 升序；全量取全部；
     - `newest_unanalyzed`：取 `analyzed == False`，按 `COALESCE(published_at, article_published_at, fetched_at)` 降序、`id` 降序，`limit(max_items_per_source)`，不依水位线筛选；
  3. per_item 逐条调 LLM 存结果；aggregate 拼接送 LLM 存汇总结果；
  4. 推进 `task_sources` 水位线（`newest_unanalyzed` 下取本批最大 `id`，仅用于监控，不参与下次筛选）；
  5. 全程写 `task_logs`，更新 `task_runs` 状态/摘要；成功后触发推送钩子 `on_analysis_completed`。
  未知 `selection_strategy` 值回退 `sequential` 并记日志；`custom` 模式不走策略分支，仅分析 `custom_item_ids`。

### 5.4 后台 Worker（services/worker.py）

进程级 `ThreadPoolExecutor`。API 创建 `task_runs(pending)` 后提交作业到 worker；作业在新线程用独立 DB 会话执行并更新状态/日志。前端轮询任务中心查看进度。

### 5.5 定时任务调度器（services/scheduler.py）

- **调度器**：进程内 APScheduler `BackgroundScheduler`（单进程；多 worker 部署需改用持久化 jobstore，见第 8 节已知约束），`MemoryJobStore`；时区取 `config.app.json` 的 `timezone_display`（默认 `Asia/Shanghai`）。由 FastAPI `lifespan` 启动时 `start_scheduler()` 加载已启用任务、关闭时 `shutdown_scheduler()`。
- **触发器**：`trigger_type=cron` 用 `CronTrigger.from_crontab(cron_expr, timezone=...)`；`trigger_type=interval` 用 `IntervalTrigger(seconds=interval_seconds, timezone=...)`。创建/更新时由 API 层校验字段并解析 cron 合法性。
- **回调 `_fire(job_id)`**：调度器触发时创建 `TaskRun(kind=analysis, ref_id=task.id, mode=sj.mode, scheduled_job_id=job_id, status=pending)`，置 `sj.last_run_at`/`last_run_status=running`，然后 `worker.submit(run_analysis, run_id, task_id, mode)`--与手动触发走同一执行路径。
- **CRUD 同步**：`add_scheduled_job / remove_scheduled_job / reschedule_scheduled_job` 在 API 创建/删除/更新/启停时同步内存调度器，DB 与调度器始终保持一致；`replace_existing=True` 避免重复添加。
- **状态回写**：`run_analysis` 结束（成功/失败）时回写 `sj.last_run_status`；`_sync_next_run` 将 APScheduler 的 `next_run_time`（Asia/Shanghai tz-aware）归一化为 UTC 后回写 `next_run_at` 供前端展示（避免 +8h 二次偏移）。
- **配置**：`scheduler.enabled` / `misfire_grace_seconds` / `max_instances` / `coalesce`（对应 APScheduler 同名参数），均支持 `ISAS_SCHEDULER_*` 环境变量覆盖；`enabled=false` 时调度器不启动。

### 5.6 推送渲染（services/push/）

- `render.py`：`PushEvent` 含 `task_name`/`result_type`/`source_name`/`content`/`created_at`，以及 `per_item` 事件的 `item_title`/`file_path`/`author`/`author_affiliation`/`article_published_at`/`page_count`。`render_events` 渲染卡片式三段式 HTML（头部+文件信息+文章信息+分析结果）与纯文本备用正文；分析结果用 `mistune`（`escape=True`，plugins `table`/`strikethrough`/`task_lists`/`url`）渲染为 HTML，原生 HTML 标签被转义防注入；空字段不显示行；内联样式兼容网页邮箱。
- `service.py`：`_to_push_event` 从 `AnalysisResult` 关联的 `InfoItem` 取文件/文章字段填充 `PushEvent`；`aggregate`（`info_item_id=None`）字段留空。
- `attachments.py`：`collect_attachments(db, results)` 为 `per_item` 结果从 `InfoItem`（原文件，仅 `local_folder`，复用 `is_relative_to(folder_path)` 校验）与 `InfoItemFigure`（图表，复用 `is_relative_to(figures_dir)` 校验）收集附件字节；单文件 10MB 上限，超限/不存在/越界跳过记日志。`email_channel.send` 有附件时用 `multipart/mixed`（正文 `alternative` + 附件 `MIMEBase`，中文文件名 RFC 2231 编码）。

## 6. API 设计（均位于 `/api` 前缀）

| 模块 | 端点 |
|---|---|
| 认证 | `POST /api/auth/login`、`GET /api/auth/me`、`POST /api/auth/logout` |
| 权限管理 | `GET /api/users`、`GET /api/users/pages`、`GET/PUT /api/users/{id}/permissions` |
| 系统配置 | `GET /api/config` |
| 任务中心 | `GET /api/task-center/runs`（支持 `kind`/`ref_id`/`status` 过滤）、`GET /api/task-center/runs/{id}`、`GET .../logs`、`DELETE .../runs/{id}` |
| 信息源 | `GET /api/info-sources/types`、`GET/POST/PUT/DELETE /api/info-sources`、`POST .../{id}/check`、`POST .../{id}/sync`、`GET .../{id}/status`、`GET .../{id}/items`、`GET .../{id}/items/{item_id}`、`POST .../items/query`（跨源条目查询，支持 `ids`/`exclude_ids`/`sort_by`/`order`/`keyword`，排序字段白名单 `title`/`published_at`/`analyzed`/`created_at` 防注入；`info_sources` 权限）、`GET .../items/{item_id}/file`（文件预览，`analysis_tasks` 权限）、`GET .../items/{item_id}/figures/{index}`（图表，`analysis_tasks` 权限）、`POST .../items/{item_id}/reextract`（重新抽取，`info_sources` 权限） |
| 分析任务 | `GET/POST/PUT/DELETE /api/analysis-tasks`、`POST .../{id}/run`、`GET .../{id}/sources`、`GET .../{id}/results`（支持 `run_id` 过滤；`per_item` 结果携带 `source_file`：filename/file_path/title/author/author_affiliation/published_at/page_count/file_url/figures，`aggregate` 为 null） |
| 定时任务 | `GET/POST /api/scheduled-jobs`、`PUT/DELETE /api/scheduled-jobs/{id}`、`POST .../{id}/toggle`、`POST .../{id}/run`（均需 `scheduled_jobs` 权限） |

> 旧全局端点 `GET /api/analysis-results` 已移除；查看结果由分析任务「结果」按钮下钻到 `/analysis-tasks/:id/results`（复用 `analysis_tasks` 权限）。SPA 兜底路由对未匹配的 `/api/*` GET 请求返回 404，不回退到 `index.html`。

> 分析结果文件服务安全：`file`/`figures` 接口需 `analysis_tasks` 页权限，`reextract` 需 `info_sources` 页权限；文件路径须 `is_relative_to` 源 `folder_path`、图表路径须 `is_relative_to` `figures_dir`（防路径穿越）；归属校验 `item.source_id == source_id`；非 `local_folder` 源文件预览 404；HTML 不作 `text/html` 服务（防 XSS，统一 `text/plain`）。

> 条目查询接口 `POST /api/info-sources/items/query`：所有过滤（`source_ids`/`analyzed`/`keyword`/`ids`/`exclude_ids`）在 SQL 层统一应用后再分页，保证每页满额（修复此前 `analyzed` 取行后 Python 二次过滤致每页不足 `limit` 的问题）；`sort_by` 经白名单校验，未知/缺省值回退 `id` 倒序，`order` 仅对白名单字段生效，防注入。前端「选择条目」弹窗据此实现已选置顶（`ids` 取已选、`exclude_ids` 去重）、列排序（`sort_by`/`order`）、标题筛选（`keyword`）。

## 7. 关键流程：增量分析

```
POST /api/analysis-tasks/{id}/run {mode:"incremental"}
  └─ 创建 task_runs(pending) → 提交 worker
       └─ engine.run_analysis
            for source in task.sources:
                items = SELECT * FROM info_items WHERE source_id=? AND id > 水位线
                per_item: LLM 分析每条 → analysis_results
                aggregate: LLM 汇总本批 → analysis_results
                推进 task_sources.last_analyzed_item_id
            task_runs → succeeded + 摘要
       └─ 全程 task_logs + 文件日志
前端轮询任务中心 / 分析任务「结果」下钻页查看（`/analysis-tasks/:id/results`，按运行批次分组+折叠 Markdown）
```

## 8. 部署与运维

见 `README.md`「部署方式」「运维方式」。支持 ps1/sh 脚本与 Linux systemd；Jenkins 流水线见 `JenkinsConfig/Jenkinsfile`。

### 配置与密钥管理

- 主配置 `config/app.json`：随代码部署，敏感字段为占位符。
- 本地覆盖 `config/env.local`：存放真实敏感配置（LLM Key、JWT 密钥、WebFetch Key 等），以 `ISAS_*` 环境变量覆盖 `app.json`；**不被 Jenkins 部署覆盖**（Jenkinsfile rsync 排除 `config/env.local`）、**不入 Git**（.gitignore 忽略）；`start.sh`/`run.sh` 启动时自动 `source`，修改后重启生效；建议 `chmod 600`。模板见 `config/env.local.example`。
- 配置优先级：环境变量（含 `env.local`）> `app.json`。
- 启停脚本（`start.sh`/`stop.sh`/`status.sh`）在以非部署属主用户运行时，自动 `sudo` 到部署目录属主（`stat` 探测）再执行，避免 `logs/`/`data/` 写权限问题。
- 端口以 `config/app.json` 的 `server.port` 为唯一来源，各脚本/Jenkinsfile/systemd 均从中读取（`ISAS_SERVER_PORT` 可覆盖）。

### 图表存储配置

- `figures_dir`（默认 `data/figures`，即 `data_dir/figures`；env `ISAS_FIGURES_DIR`）：内嵌图表落盘根目录，启动时自动创建。
- `max_figures_per_item`（默认 20；env `ISAS_MAX_FIGURES_PER_ITEM`）：单文件图表抽取上限，超出截断并记日志。

### 正文抽取配置（视觉兜底）

- `extraction.vision_fallback`（默认 true；env `ISAS_EXTRACTION_VISION_FALLBACK`）：是否启用 PDF 视觉 LLM 兜底抽取。
- `extraction.vision_model`（默认空，复用 `llm.model`；env `ISAS_EXTRACTION_VISION_MODEL`）：视觉兜底专用模型，留空则复用分析模型。需支持视觉的多模态模型。
- `extraction.max_ocr_pages`（默认 10；env `ISAS_EXTRACTION_MAX_OCR_PAGES`）：单文件视觉兜底最大渲染页数，超出截断并记日志。
- `extraction.min_text_length`（默认 50；env `ISAS_EXTRACTION_MIN_TEXT_LENGTH`）：文本层可读非空白字符数下限。
- `extraction.readable_ratio`（默认 0.6；env `ISAS_EXTRACTION_READABLE_RATIO`）：文本层可读字符占比阈值，低于则判定不可用并触发兜底。
- `extraction.render_dpi`（默认 150；env `ISAS_EXTRACTION_RENDER_DPI`）：视觉兜底页面渲染 DPI。

### 存量回填

首次部署后，对现有 `local_folder` 信息源触发一次同步（同步会补齐存量元数据/图表，并对 `extraction_method='none'` 或 `content` 为空的历史条目重新走视觉兜底），或对单个文件调用 `POST /api/info-sources/{source_id}/items/{item_id}/reextract` 手动重新抽取。

### 已知约束

- 定时任务调度器为进程内 APScheduler `BackgroundScheduler` + `MemoryJobStore`，单进程运行；若未来以多 worker（如 `uvicorn --workers N`）部署，需改用持久化 jobstore（如 `SQLAlchemyJobStore`）并加分布式锁，避免重复触发。当前部署为单 worker，无此问题。
